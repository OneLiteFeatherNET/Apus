# Apus Phase 5a — API and Authorization: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A REST and SSE interface over the Custom Resources that enforces tenant separation — so the UI from Phase 5b can build on top of it and nobody has to write YAML.

**Architecture:** Micronaut. The Custom Resources are the source of truth; the API holds no copy of its own, but reads through the Fabric8 client. **The API is the enforcement point for authorization**: it checks the caller's permissions first, then talks to the Kubernetes API using its own ServiceAccount — no impersonation. The tenant comes from the token, never from the request.

**Tech Stack:** Java 25, Micronaut, Micronaut Security (JWT validation against an OIDC issuer), Fabric8 7.8.0, JUnit Jupiter.

## Global Constraints

- Java toolchain 25, base package `net.onelitefeather.apus.api`, new module `api`.
- **The tenant is derived exclusively from the token.** No endpoint accepts a tenant or namespace as a parameter. This is the central security rule of this phase: if an endpoint took the namespace from the request, any user could access other tenants.
- **Roles:** `platform-admin` (everything), `tenant-owner` (everything within their own tenant, including members), `tenant-operator` (maintain sources and maps, trigger renders), `tenant-viewer` (read-only). From §10.3 of the spec.
- Credentials and secret contents **never** appear in responses.
- Errors give no indication of the existence of other tenants' resources: a resource in a foreign tenant is treated as "not found," not as "forbidden" — otherwise the API becomes a directory of other tenants.
- AGPL header via Spotless, Conventional Commits, **no** Claude attribution, English.

### What already exists

All Custom Resources from Phases 2a, 2b, and 3 under `net.onelitefeather.apus.operator.api`: `Tenant`, `BlueMapMap`, `BlueMapRender`, `WorldSource`, `WorldIngest`, `BlueMapHosting`. The `operator` module can be pulled in as a dependency — the classes are pure data holders without logic, which is exactly why they were cut that way.

`TenantReconciler.namespaceFor(...)` maps the tenant name to the namespace; the namespace carries a label with the tenant name.

### Task 1: Module, Authentication, and Tenant Resolution

**Files:**

- Modify: `settings.gradle.kts` (module `api`, Micronaut entries in the catalog)
- Create: `api/build.gradle.kts`
- Create: `api/src/main/java/net/onelitefeather/apus/api/security/ApusPrincipal.java`
- Create: `api/src/main/java/net/onelitefeather/apus/api/security/TenantResolver.java`
- Create: `api/src/main/java/net/onelitefeather/apus/api/security/Role.java`
- Tests for it

**Interfaces:**

```java
public enum Role { PLATFORM_ADMIN, TENANT_OWNER, TENANT_OPERATOR, TENANT_VIEWER }

/** Who is calling, derived solely from the validated token. */
public record ApusPrincipal(String subject, String tenant, Set<Role> roles) {
    public boolean isPlatformAdmin();
    public boolean canWrite();     // owner or operator
}

public final class TenantResolver {
    /** @return the namespace this principal may act in
     *  @throws ForbiddenException when the principal has no tenant */
    public String namespaceFor(ApusPrincipal principal);
}
```

**Actually research the Micronaut version** against Maven Central and enter it into the inline version catalog. For token validation, `micronaut-security-jwt` against a configurable issuer is sufficient — which identity broker sits in front of it is deliberately left open (§15 of the spec).

**Tests that lock down the core:**

- A token without a tenant claim results in a rejection, not a default tenant.
- A `platform-admin` may act across tenants; a `tenant-viewer` may not write.
- The namespace is derived exclusively from the token's tenant — there is no path by which a parameter can influence it.

### Task 2: Read and Write Endpoints *(parallel with Task 3)*

> Own worktree. Check the base first (`git log --oneline -1`). Only files under `api/src/main/java/net/onelitefeather/apus/api/rest/` and their tests.

Endpoints per §11.1 of the spec:

| Endpoint | Role |
| --- | --- |
| `GET /api/tenants`, `POST /api/tenants` | `platform-admin` only |
| `GET /api/sources`, `POST /api/sources` | own tenant |
| `GET /api/maps`, `GET /api/maps/{id}` | own tenant |
| `POST /api/maps/{id}/render` | write-permitted; creates a `BlueMapRender` |
| `GET /api/renders`, `GET /api/renders/{id}` | own tenant |
| `GET /api/hostings` | own tenant |

**Binding:** Every endpoint derives the namespace from the token via `TenantResolver`. A resource that doesn't exist in the caller's own namespace results in a 404 — even if it exists in a foreign one.

**Response models are their own types**, not pass-through Custom Resources. A Custom Resource carries fields that are nobody else's business (finalizers, `resourceVersion`, managed fields) — and would unintentionally change the public interface with every CRD change.

**Tests:** for each endpoint, the happy path, the "foreign tenant results in 404" case, and the "insufficient role results in 403" case.

### Task 3: Progress and Logs as an Event Stream *(parallel with Task 2)*

> Own worktree. Only files under `api/src/main/java/net/onelitefeather/apus/api/events/` and their tests.

- `GET /api/renders/{id}/events` — SSE with the progress from `BlueMapRender.status.progress`. The values are already in the status; the operator keeps them up to date. Watch the resource instead of polling.
- `GET /api/renders/{id}/logs` — SSE with the log lines of the associated job.

**On the log source:** §11.1 names Loki, because Alloy already collects all pod logs in the cluster anyway, so the API needs no pod access. Check whether a Loki instance is reachable via configuration; if it isn't, the fallback is direct log retrieval through the Kubernetes client. **Make a reasoned decision and document it** — the direct route needs more permissions for the ServiceAccount, which the spec deliberately wanted to avoid.

**Binding:** The tenant check applies here too. A render belonging to a foreign tenant results in a 404 before any stream is opened — otherwise logs from other tenants could be read along with it.

**Tests:** The stream delivers progress values on status change; a foreign render results in 404; the stream ends cleanly when the render becomes terminal (otherwise every viewer holds a connection open indefinitely).

### Task 4: Integration Test

Against k3s with the real CRDs: create resources, query them through the API, verify tenant separation. In particular: a token for tenant A must be able to neither see nor modify resources of tenant B — with a real API server, not just against mocks.

Its own `integrationTest` task, not part of `build`.
